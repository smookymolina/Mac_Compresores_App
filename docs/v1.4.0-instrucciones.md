## 2. Antes de probar: respaldo

En el servidor de producción, **antes** de cualquier prueba o despliegue:

```bash
docker compose -f docker-compose.prod.yml exec db pg_dump -U mac --no-owner mac_compresores \
  | gzip > respaldo_pre_v1.4.0_$(date +%F).sql.gz
```

Copia ese archivo a tu computadora; con él montas la prueba local.

## 3. Prueba local de la web (Docker)

Pasos detallados en `docs/v1.4.0-pruebas-locales.md`. Resumen:

1. `git fetch && git checkout v1.4.0`
2. Crea `.env.v140` desde `.env.example` con `SEED_DEMO=0`, `SMTP_*` vacíos, `CRON_SECRET` vacío y `COOKIE_SECURE=false`.
3. Levanta solo la base: `docker compose -p mac-v140 --env-file .env.v140 up -d db`.
4. Restaura el respaldo con `gunzip -c respaldo.sql.gz | docker compose … exec -T db psql -U mac -d mac_compresores`.
5. Migra y levanta la app: `docker compose -p mac-v140 --env-file .env.v140 up -d --build db migrate app`.
6. Entra a <http://localhost:3080> con tu usuario de siempre y recorre la lista de la guía: cotización → PDF → venta → pago, importación de productos y comisiones.

⚠️ **Nunca** apuntes la prueba a la base de producción. Deja el correo vacío para que no salgan correos a clientes reales.

## 4. Probar la app móvil contra tu Docker local

### 4.1 Preparar el servidor local
1. Usa la IP de tu computadora en la red Wi-Fi (p. ej. `192.168.1.50`). El teléfono debe estar en la **misma red**.
2. Revisa que el puerto 3080 esté abierto en el firewall de tu computadora. Prueba desde el navegador del teléfono: `http://192.168.1.50:3080/api/app/version` debe responder un JSON.
3. En la web local: **Usuarios** → marca **«App móvil»** en el usuario que vas a probar.

### 4.2 Obtener el APK de prueba
El APK se compila en GitHub Actions; aquí no hay SDK de Android.
1. GitHub → **Actions** → **Mobile Android (MAC Campo)** → **Run workflow**.
2. Rama `v1.4.0` y en `api_url` escribe `http://192.168.1.50:3080`.
3. Al terminar, descarga el artefacto `mac-campo-1.4.0-debug` y descomprímelo: dentro viene `app-debug.apk`.

El APK *debug* permite HTTP para la prueba local. El de producción (*release*) solo acepta HTTPS.

### 4.3 Instalar en Android
1. Pasa el `.apk` al teléfono (cable, WhatsApp o Drive) y ábrelo.
2. Acepta **«Permitir de esta fuente»**. Si Play Protect avisa «app no reconocida», elige **Instalar de todas formas**; es normal en apps privadas.
3. Abre **MAC Campo**:
   1. Entra con tu correo y contraseña de la web.
   2. Crea un **PIN** de 4 a 6 dígitos (y activa la huella si quieres).
   3. Espera la **descarga inicial**. El catálogo completo tarda unos minutos la primera vez.

### 4.4 Qué revisar (fase 2)
- [ ] El inicio de sesión funciona. Un usuario **sin** «App móvil» recibe el mensaje «Tu usuario no tiene acceso a la app móvil».
- [ ] Al cerrar y abrir la app pide PIN o huella. Con 5 PIN incorrectos se borran los datos locales y vuelve a pedir inicio de sesión.
- [ ] El catálogo encuentra productos por SKU, número de parte y descripción **en modo avión**.
- [ ] El detalle de producto muestra precio, IVA y existencias, y **nunca** el costo (con usuario de Ventas).
- [ ] En Clientes aparecen solo los del vendedor y los sin asignar, con sus cotizaciones y ventas.
- [ ] Cambia el precio de un producto en la web, toca **«Sincronizar ahora»** y verifica que el cambio llega al teléfono.
- [ ] Reasigna un cliente a otro vendedor y sincroniza: debe desaparecer del teléfono.
- [ ] En la web, **Sincronización** → **Revocar** el dispositivo: en la siguiente sincronización la app borra sus datos y pide iniciar sesión.
- [ ] La barra de estado muestra 🟢 En línea, 🟠 Sin conexión y 🔄 Sincronizando… según corresponda.

### 4.5 Qué revisar (fases 3 y 4) — en modo avión y luego con red
- [ ] Nueva cotización con un cliente y 2–3 productos: totales iguales a la web; descuento > 15 % bloqueado para Ventas; PDF y «Compartir» funcionan sin red; folio C-n apartado.
- [ ] Al reconectar: la cotización aparece en la web con el mismo folio y totales; «Enviar por correo» capturado sin red se envía (con SMTP vacío solo queda en auditoría).
- [ ] Cambia el precio de un producto en la web, cotízalo en el teléfono **sin sincronizar** y luego sincroniza: dentro de 3 días se respeta el precio del teléfono; fuera de la ventana aparece en **Sincronización** con «Aplicar precio actual / Respetar precio del teléfono / Rechazar».
- [ ] Clientes: alta y edición sin red; edita en la web otro campo del mismo cliente → al sincronizar se conservan ambos cambios.
- [ ] Ventas: «Convertir en venta» de una cotización aceptada sin red → «Venta pendiente»; al sincronizar se confirma y descuenta inventario. Sin existencia → conflicto en Sincronización («Convertir desde otro almacén» / «Reintentar» / «Rechazar»).
- [ ] Pagos sobre una venta confirmada; un pago mayor al saldo se rechaza con mensaje claro.
- [ ] Almacén (usuario ALMACÉN): entradas y salidas sin red; una salida sin existencia queda en conflicto.
- [ ] Más → Pendientes / incidencias muestra todo lo que el servidor rechazó o dejó en revisión.

### 4.6 iPhone (fase 5 bis)
iOS no permite HTTP ni instalar archivos sueltos: necesitas **HTTPS** y la app **firmada** con tu cuenta Apple Developer.
1. Expón tu Docker local con HTTPS (p. ej. `cloudflared tunnel --url http://localhost:3080` o `ngrok http 3080`) y usa esa URL como `APP_URL` y como `api_url` del workflow.
2. Registra el UDID del iPhone en developer.apple.com → crea el perfil **Ad Hoc** → carga los secrets `IOS_*` (ver `mobile/README.md`).
3. GitHub → Actions → **Mobile iOS (MAC Campo)** → `export_method = ad-hoc` → descarga el `.ipa` del artefacto.
4. En la web local: Sincronización → «Versiones de la app» → **iOS (Ad Hoc)** → sube el `.ipa`. En el iPhone abre `https://<túnel>/app` → **«Instalar en iPhone»** → Ajustes → General → VPN y gestión de dispositivos (si lo pide).
5. Alternativa sin UDID: `export_method = app-store` con los secrets `ASC_*` → TestFlight.

## 5. Configuración para producción

- **Variable** `MOBILE_API_URL` en GitHub (*Settings → Secrets and variables → Actions → Variables*) = `https://<tu dominio>`.
- **Llave de firma Android**: créala con `keytool`, como indica `mobile/README.md`, y guárdala **fuera del repositorio** con 2 respaldos. Si se pierde, los usuarios tendrían que desinstalar la app para recibir actualizaciones. En los *secrets* del repo van `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS` y `ANDROID_KEY_PASSWORD`.
- **Servidor**: `APP_DOWNLOAD_SECRET` en `.env` (`openssl rand -hex 32`) y el volumen `releases/` (guarda los APK; inclúyelo en respaldos).
- **Versión de la app**: se publica en **Sincronización → «Versiones de la app»** (archivo APK, versión, versión mínima, notas, enlace iOS). Ver `docs/mac-campo-publicar-version.md`.
- **iOS**: cuenta Apple Developer (USD 99/año), secrets `IOS_CERT_P12_BASE64`, `IOS_CERT_PASSWORD`, `IOS_PROVISION_PROFILE_BASE64`, `IOS_TEAM_ID` (y `ASC_*` para TestFlight); `APP_URL` con HTTPS; nginx con `client_max_body_size 210m` en `/api/app/releases/ios`.

## 6. Despliegue a producción (cuando las pruebas pasen)

1. Respaldo (paso 2).
2. Agrega `APP_DOWNLOAD_SECRET` a `.env` (`openssl rand -hex 32`) y verifica que el volumen `releases/` esté montado.
3. Desplegar la rama aprobada como siempre. El servicio `migrate` aplica `offline_sync` automáticamente.
4. Revisa que `select count(*) from pg_trigger where tgname like 'sync_%'` devuelva **13**.
5. Publica el APK firmado en «Versiones de la app» y activa «App móvil» según el piloto (`docs/piloto-v1.4.0.md`): 2 usuarios la semana 1, los 5 la semana 2.
6. **Plan de regreso**: desactiva «App móvil» a todos (la app deja de sincronizar; la web sigue igual). La migración solo agrega estructura, así que la versión anterior funciona sobre ella. Si algo falla, vuelve a desplegar `v1.3.18`. Solo si hiciera falta, restaura el respaldo.

## 8. Notas técnicas

- **CI:** el workflow `ci.yml` ahora instala `poppler-utils`. La prueba del PDF necesitaba `pdftotext` y fallaba también en `main` desde la v1.3.6.
- **Base de datos local del teléfono:** SQLite cifrada (SQLCipher). Las copias de seguridad de Android están desactivadas, así que esos datos no se suben a la nube.
- **Límites:** después de 7 días sin sincronizar la app avisa y bloqueará capturas (desde la fase 3). La API acepta solo la versión 1 del protocolo de sincronización.
- **Pendientes conocidos:**
  - Al guardar un cliente desde el teléfono se reemplaza el registro completo; la fusión por campo llega en la fase 4.
  - Si el servidor se cae a la mitad de un cambio de estado o de una venta, el reenvío puede reportarse como rechazado aunque sí se aplicó.
  - El diseño a 360 px de ancho falta revisarlo en un teléfono real.

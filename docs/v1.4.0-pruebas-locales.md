# v1.4.0 — Pruebas locales con copia de producción (Docker)

Objetivo: correr la rama `v1.4.0` (sincronización offline para la app móvil) en una máquina local con una **copia** del respaldo de producción y comprobar que la web sigue igual.

> **ADVERTENCIA**
> - **Nunca** apuntes esta instalación a la BD de producción (no copies el `DATABASE_URL` ni el `POSTGRES_PASSWORD` del servidor). Usa siempre el Postgres del `docker-compose.yml` local.
> - La copia trae correos y teléfonos **reales** de clientes: deja `SMTP_*` vacíos para que no salga ningún correo (recordatorios, cotizaciones, avisos).
> - `SEED_DEMO=0`: con datos reales no se deben sembrar datos `[DEMO]`.
> - Borra la copia al terminar (`docker compose -p mac-v140 down -v`).

## 1. Preparar

```bash
git checkout v1.4.0
cp .env.example .env.v140      # archivo aparte, solo para esta prueba
```

En `.env.v140` deja como mínimo:

```dotenv
POSTGRES_PASSWORD=solo_local_v140
SEED_ADMIN_PASSWORD=una-clave-local-larga   # solo se usa si el admin no existe; no cambia usuarios existentes
SEED_DEMO=0
COOKIE_SECURE=false
APP_URL=http://localhost:3080
SMTP_HOST=
SMTP_USER=
SMTP_PASS=
CRON_SECRET=                                # vacío: el scheduler no ejecuta el trabajo diario
```

Usa un nombre de proyecto propio (`-p mac-v140`) para no mezclar volúmenes con otra instalación local.

## 2. Restaurar el respaldo

El servicio `backup` genera `backups/mac_compresores_AAAA-MM-DD_HHMM.sql.gz` (`pg_dump --no-owner --no-privileges`). Copia uno desde el servidor (scp) a tu máquina.

```bash
# Solo la BD (volumen nuevo y vacío)
docker compose -p mac-v140 --env-file .env.v140 up -d db

# Restaurar (la BD mac_compresores ya existe vacía)
gunzip -c ~/Descargas/mac_compresores_2026-10-18_0900.sql.gz \
  | docker compose -p mac-v140 --env-file .env.v140 exec -T db \
    psql -v ON_ERROR_STOP=1 -U mac -d mac_compresores

# Comprobar
docker compose -p mac-v140 --env-file .env.v140 exec db \
  psql -U mac -d mac_compresores -c 'select count(*) from "Quote"' -c 'select migration_name from "_prisma_migrations" order by finished_at desc limit 3'
```

## 3. Migrar y levantar la app

```bash
docker compose -p mac-v140 --env-file .env.v140 up -d --build db migrate app
docker compose -p mac-v140 --env-file .env.v140 logs migrate   # debe aplicar 20261019165215_offline_sync
```

El servicio `migrate` corre `prisma migrate deploy` y luego el seed (idempotente: no modifica usuarios, productos ni ajustes existentes). No levantes `backup` ni `scheduler` en esta prueba.

Verificación rápida de la migración:

```bash
docker compose -p mac-v140 --env-file .env.v140 exec db psql -U mac -d mac_compresores \
  -c "select count(*) from pg_trigger where tgname like 'sync_%'"   # 13
```

App en <http://localhost:3080>; entra con tu usuario real (la contraseña es la de producción).

## 4. Checklist: la web no cambió

- [ ] Login, panel y menú iguales; «Sincronización» aparece solo con permiso `users.manage`.
- [ ] Cotización nueva → partidas con precios del catálogo → guardar → folio consecutivo correcto.
- [ ] PDF de la cotización (diseño, totales, datos bancarios si hay `BANK_INFO`).
- [ ] Cambiar estado (Enviada → Aceptada) y **convertir a venta**: existencias bajan en el almacén elegido.
- [ ] Registrar pago y anularlo; saldo en Cobranza correcto.
- [ ] Importación CSV de productos (crear y actualizar precios); historial de precios.
- [ ] Comisiones: calcular un periodo existente y comparar con producción (mismos importes).
- [ ] Reportes/exportaciones y enlace de WhatsApp de cotización abren bien.
- [ ] Vendedor (rol Ventas): solo ve sus clientes, cotizaciones y ventas; sin costos.
- [ ] Portal de socios `/socios` sigue funcionando.

## 5. Activar «App móvil» para un usuario

1. Como administrador: **Usuarios** → abrir el usuario → recuadro «App móvil» → marcar **Acceso a la app móvil** → **Guardar acceso** (aparece la etiqueta «App móvil»).
2. Los dispositivos registrados se ven y revocan en **Sincronización**. Quitar el acceso revoca todos sus dispositivos al instante.
3. Usuario inactivo o sin acceso móvil → 403 en cualquier llamada; dispositivo revocado → 401.

## 6. API de sincronización con curl

Todas las rutas `/api/sync/*` exigen `X-Sync-Protocol: 1` (otro valor → 409 con `upgrade: true`). Todas salvo `register` exigen `Authorization: Bearer <token>`.

```bash
B=http://localhost:3080
P='X-Sync-Protocol: 1'

# Versión de la app (público, sin cabeceras)
curl -s $B/api/app/version

# Registro del dispositivo (devuelve el token UNA sola vez; 5 intentos fallidos por correo / 15 min)
curl -s -X POST $B/api/sync/register -H "$P" -H 'Content-Type: application/json' \
  -d '{"email":"vendedor@ejemplo.mx","password":"…","deviceName":"Pixel prueba","platform":"ANDROID","appVersion":"1.4.0"}'
TOKEN=...   # campo "token" de la respuesta
A="Authorization: Bearer $TOKEN"

# Descarga inicial por entidad: Product, Customer, Quote, Sale, StockBalance, Warehouse, ExchangeRate, ComplementPackage
curl -s "$B/api/sync/bootstrap?entity=Customer&limit=500" -H "$A" -H "$P"          # trae serverSeq
curl -s "$B/api/sync/bootstrap?entity=Customer&after=<next>&limit=500" -H "$A" -H "$P"

# Cambios desde un cursor (usa serverSeq / el cursor anterior)
curl -s "$B/api/sync/pull?cursor=0&limit=500" -H "$A" -H "$P"

# Apartar folios para cotizar sin conexión (1–25)
curl -s -X POST $B/api/sync/folios -H "$A" -H "$P" -H 'Content-Type: application/json' -d '{"count":5}'

# Enviar comandos (idempotente por id; reenviar el mismo id devuelve el mismo resultado)
curl -s -X POST $B/api/sync/push -H "$A" -H "$P" -H 'Content-Type: application/json' -d '{
  "commands":[{"id":"6f1c2a3e-0000-4000-8000-000000000001","type":"quote.status",
               "capturedAt":"2026-10-19T12:00:00Z",
               "payload":{"quoteId":"<uuid de una cotización propia>","to":"SENT"}}]}'

# Cerrar sesión (revoca el dispositivo)
curl -s -X POST $B/api/sync/logout -H "$A" -H "$P"
```

Tipos de comando: `customer.save`, `quote.create`, `quote.update`, `quote.status`, `sale.convert`, `payment.register` (mismos permisos que la web). Resultados: `APPLIED`, `REJECTED`, `CONFLICT` (se revisan en **Sincronización**) o `retry`.

## 7. Limpiar

```bash
docker compose -p mac-v140 --env-file .env.v140 down -v   # borra contenedores y la copia de la BD
rm .env.v140 ~/Descargas/mac_compresores_*.sql.gz
```
